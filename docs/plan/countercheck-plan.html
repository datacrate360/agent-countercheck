Countercheck: plan

From a working CLI to a product people rely on. Companion to docs/design/countercheck-design.html. Durations assume part-time work (evenings and weekends) with AI coding agents doing most of the typing.

In plain words We already have the engine: countercheck verify catches an agent's false "done" (v0.1, 22 tests, verifies its own repo). The plan now has one rule: prove people want it before building the big version. So the first steps make Countercheck effortless to try and put it in front of real users; the bigger pieces (app, signing, real-system checks) come only after users say yes.

5. Risks and answers

RiskAnswer
People prefer their own small hook scriptsMake install + init take under a minute, and show what DIY hooks miss (locked checks, restored tests, sandbox, receipt)
Vendors add the same check to their own agentStay cross-vendor and neutral; vendors check only themselves (research T7)
Vendor rule changes break hooksDepend on outputs (git, files, logs), keep a plain CLI path that always works
Projects whose tests need network or servicesClear "unverified: needs network" reason now; opt-in network allowlist later
