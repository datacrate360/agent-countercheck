1. The confusion, in plain words

In plain words Every tool says it does "everything", so their features overlap: Hermes has a work board, OpenClaw has a canvas, both have memory. That makes it look as if you must pick one philosophy or install all of them.

The way out: stop comparing tools; list the jobs. An AI ecosystem has about ten jobs. For each job, pick one owner. A tool's side feature counts only if it does the job well enough for you. If it does, you don't need the dedicated tool. If it doesn't, you add the dedicated tool for that job only, connected through a standard plug (MCP, a CLI or an HTTP API).

Think of a kitchen. Your oven has a timer, but if you bake bread every day you may still buy a proofing box. The question is never "does my oven have a timer?" but "is the timer good enough for what I cook?".

2. The jobs of an AI ecosystem

Two rules hold the whole picture together: (1) brains are swappable: every serious harness can call several model providers; (2) the jobs above the worker connect through three plugs only: MCP (tool calls), CLI (run a program) and HTTP (web API), plus Git for code. Anything that speaks one of those can join.

4. "Do I still need tool X?": the decision rule

Three rules of thumb
  • One owner per job. Two memories or two boards drift apart and confuse the agent. If you add Paperclip, stop using Hermes's Kanban for the same work.
  • Philosophy only matters where jobs overlap. Hermes ("grows with you"), OpenClaw ("in your chats"), Paperclip ("a company of agents") don't compete when each owns a different job: Paperclip manages, Hermes works, graphify maps code.
  • Prefer the plug over the merge. Tools that connect through MCP/CLI/HTTP can be swapped next year. Copying their code into yours can't.

7. omni-agent design

One sentenceomni-agent checks whether AI work really happened and really works, for any agent, and tells you what it cost. It doesn't plan, write code, or chat: it owns job 7, proof, and stays small so it can sit beside every other tool.

Principles

  • The worker never grades itself: checks come from the base revision; protected files are restored.
  • Evidence, not opinions: run commands and read real systems; AI judgement only where nothing can be run, and labelled as such.
  • Honest verdicts: verified / failed / unverified with plain reasons. Low noise beats wide coverage.
  • Plug in, don't take over: hooks, CLI, CI, MCP, adapters.
  • Local-first and safe by default: sandboxed checks, no telemetry, one binary.

Components

  • omni-core (Rust, pure): check file, protected paths, receipts, verdict rules, seal. Built.
  • omni CLI: git snapshot, sandbox runner, verify / init / show. Built (v0.1).
  • Hooks installer: omni hook install claude-code|codex. Next.
  • Cost readers: agent session logs → dollars per receipt. Next.
  • Receipt signing (Ed25519) + receipt store (SQLite). Planned.
  • MCP server, GitHub Action, Paperclip/Linear adapters. Planned.
  • Read-back connectors (DB, HTTP, CRM). Planned.
  • Receipts app (Tauri + React) and launcher listing. Planned.
